# Синхронизация: свои файлы на сервере и на компьютере

*freemind-setup · модуль `sync` · ставится после Гермеса*

**Зачем.** Гермес живёт на сервере, и всё, что он делает для тебя — тексты, таблицы, отчёты, картинки, — тоже остаётся на сервере. Каждый раз вытаскивать файл оттуда руками неудобно. После настройки у тебя будет одна папка, которая лежит **и на сервере, и на твоём компьютере**: Гермес положил туда файл — через пару секунд он у тебя на рабочем столе. Ты бросил туда документ — Гермес его уже видит.

**Сколько времени.** 20–30 минут. На сервере — одна команда. Остальное — мышкой в двух окнах браузера.

**Что нужно.** Гермес уже стоит (`install.sh hermes`, см. [README](README.md)), Netcatty умеет заходить на сервер, компьютер — Mac или Windows.

## Как это работает

На сервер и на компьютер ставится одна и та же бесплатная программа — **Syncthing**. Две копии знакомятся друг с другом по ID (длинный код из букв и цифр) и дальше сами следят за одной папкой. Изменился файл с одной стороны — копия тут же уезжает на другую. Напрямую, без облака посередине: файлы не лежат ни у какой компании.

```
   Сервер (Гермес)                         Твой компьютер
  ┌─────────────────┐                   ┌─────────────────┐
  │  ~/Проекты      │ ◄──── Syncthing ──► │  Проекты        │
  │  (сюда пишет    │   в обе стороны,  │  (обычная папка │
  │   Гермес)       │   через интернет  │   в Finder/     │
  └─────────────────┘                   │   Проводнике)   │
                                        └─────────────────┘
```

**Что синхронизируем.** Одну рабочую папку проектов — `~/Проекты` на сервере. В идеале все твои проекты живут внутри неё, каждый в своей подпапке. Синхронизация в обе стороны, и у каждого удалённого или перезаписанного файла 30 дней хранится прошлая версия.

**Что НЕ синхронизируем — и почему:**

| Что | Почему |
|---|---|
| Папка Гермеса `~/.hermes` | там ключи, токен бота и его база данных. Базу, в которую пишут с двух сторон одновременно, синхронизация портит |
| `.env`, ключи (`*.key`, `*.pem`, `id_rsa…`), папка `.ssh` | секреты не должны уезжать с устройства, где они нужны. Утечёт ноутбук — утечёт и сервер |
| `.git`, `node_modules`, `.venv`, `__pycache__` | служебное программ: тысячи мелких файлов, которые пересоздаются сами |
| `.DS_Store`, `Thumbs.db`, `desktop.ini` | мусор Mac и Windows. Из-за него синхронизация может «висеть на 95%» |

Список исключений установщик сам запишет в файл `.stignore` внутри папки. Этот же список ты вставишь на компьютере в [шаге 3](#шаг-3-знакомим-сервер-и-компьютер).

## Шаг 1. На сервере: одна команда

Зайди на сервер через Netcatty, как при установке Гермеса. Скопируй команду целиком, вставь, нажми Enter:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/freemind-club/freemind-setup/main/install.sh) sync
```

| Установщик спрашивает | Что делаешь |
|---|---|
| *Бегут строки про Syncthing и ключ* | ставится Syncthing из его официального репозитория. Строка «Ключ Syncthing проверен» значит, что программа настоящая |
| «Папка для синхронизации [/root/Проекты]» | просто **Enter**. Хочешь другое имя — впиши, например `/root/Работа`. Дальше в инструкции везде, где `~/Проекты`, подставляй своё |
| «ID компьютера (Enter — пропустить)» | просто **Enter**. Syncthing на компьютере ещё не стоит — к этому вопросу вернёмся в шаге 3 |

В конце установщик напечатает рамку. Главное в ней — **ID сервера**: восемь групп по семь знаков через дефис, вида `XXXXXXX-XXXXXXX-…`. Выдели его целиком и скопируй — он нужен на компьютере.

Всё, что в рамке, сохранено в файл. Потерял ID — набери на сервере:

```bash
cat ~/sync-info.txt
```

> **Повторный запуск безопасен.** Что-то пошло не так или хочешь добавить компьютер позже — запускай ту же команду ещё раз. Уже сделанное установщик пропустит, твои настройки не перезапишет.

## Шаг 2. На компьютере: ставим Syncthing

**Mac.** Открой [страницу загрузки Syncthing для macOS](https://github.com/syncthing/syncthing-macos/releases/latest). Внизу, в списке файлов, скачай `Syncthing-…dmg`. Открой его и перетащи Syncthing в «Программы». Запусти — справа вверху, в строке меню, появится значок Syncthing.

Если Mac пишет «не удаётся проверить разработчика»: правой кнопкой по Syncthing в «Программах» → **Открыть** → **Открыть**.

**Windows.** Открой [страницу загрузок Syncthing](https://syncthing.net/downloads/) и найди там **Syncthing Windows Setup** — это установщик, который сам сайт Syncthing советует для Windows. Он ведёт на [свою страницу загрузки](https://github.com/Bill-Stewart/SyncthingWindowsSetup/releases/latest): скачай `syncthing-windows-setup-…exe` и запусти. На вопросы установщика отвечай по умолчанию.

**Открой Syncthing на компьютере.** Его окно — это страница в браузере: `http://127.0.0.1:8384`. На Mac — клик по значку в строке меню → **Open** (Открыть). На Windows — ярлык Syncthing в меню «Пуск» или просто вставь этот адрес в браузер.

**Где ID компьютера:** вверху справа **«Действия» → «Показать ID»**. Он нам понадобится в шаге 3.

> **Где положить папку на компьютере.** В домашней папке — `Проекты` рядом с «Документами» и «Загрузками». **Не внутри Яндекс.Диска, iCloud Drive, OneDrive или Dropbox**: две синхронизации одной папки дерутся друг с другом и плодят копии. На Mac с включённой опцией iCloud «Рабочий стол и Документы» не клади папку и в «Документы».

## Шаг 3. Знакомим сервер и компьютер

Знакомство взаимное: компьютер должен знать сервер, а сервер — компьютер.

### 3.1. На компьютере добавь сервер

В окне Syncthing на компьютере (`http://127.0.0.1:8384`):

1. Внизу справа — **«Добавить удалённое устройство»**.
2. **«Идентификатор устройства»** — вставь ID сервера из шага 1.
3. **«Имя устройства»** — например, `Сервер`.
4. **«Сохранить»**.

### 3.2. На сервере добавь компьютер — выбери один путь

**Вариант А. Без браузера — проще.** Скопируй ID компьютера («Действия» → «Показать ID»), зайди на сервер через Netcatty и запусти **ту же команду из шага 1** ещё раз. На вопрос про папку — Enter. На вопрос «ID компьютера» — вставь ID и Enter. Установщик сам добавит компьютер и откроет ему папку.

**Вариант Б. Через окно Syncthing на сервере.** Оно открыто только для самого сервера, а к тебе попадает через SSH-тоннель — так же, как веб-интерфейс Гермеса (порт 9119). Открой на компьютере терминал (Mac — «Терминал», Windows — PowerShell) и введи, подставив свой IP:

```bash
ssh -L 8385:127.0.0.1:8384 root@IP_сервера
```

Введи пароль от сервера и **не закрывай это окно**. Теперь в браузере открой `http://127.0.0.1:8385`.

> **Почему 8385, а не 8384.** На 8384 у тебя уже живёт Syncthing компьютера. 8385 — это окно Syncthing **сервера**. Две вкладки выглядят одинаково: смотри на имя устройства в левом верхнем углу.

<details>
<summary><b>То же самое кнопками в Netcatty (без терминала)</b></summary>

1. Слева в меню открой раздел **«Проброс портов»**.
2. Нажми **«Новое правило»**.
3. Тип: **«Локальный»** → **«Продолжить»**.
4. **«Номер локального порта»**: `8385`. **«Адрес привязки»** не трогай → **«Продолжить»**.
5. **«Адрес назначения»**: `127.0.0.1`, **«Номер порта назначения»**: `8384` → **«Продолжить»**.
6. **«Выберите SSH-сервер»**: выбери свой сервер → **«Продолжить»**.
7. **Метка**: например, `Syncthing сервер` → **«Готово»**.
8. Запусти правило и открой в браузере `http://127.0.0.1:8385`.

Названия кнопок взяты из русского перевода Netcatty — в твоей версии они могут чуть отличаться словами.

</details>

В окне сервера (`8385`) сверху появится жёлтая плашка: **устройство такое-то хочет подключиться**. Нажми **«Добавить устройство»**, на вкладке **«Совместный доступ»** (Sharing) поставь галочку на папке **«Проекты»** → **«Сохранить»**.

Если Syncthing показывает плашку, что на его окно не задан пароль, — для окна сервера это не страшно: оно открыто только для самого сервера, и попасть в него можно лишь через твой тоннель.

### 3.3. На компьютере прими папку

Через несколько секунд в окне компьютера (`8384`) появится плашка: **«Сервер» хочет поделиться папкой «Проекты»**. Нажми **«Добавить»**. Откроется окно папки — пройди по вкладкам **до того, как нажмёшь «Сохранить»**:

1. **«Общие»** → **«Путь к папке»**: где папка будет лежать на компьютере. Обычно Syncthing сам подставляет `Проекты` в домашней папке — это то, что нужно.
2. **«Шаблоны игнорирования»** (Ignore Patterns) — вставь этот список целиком. Это тот же список, что установщик записал на сервер: без него секреты и мусор с компьютера уедут на сервер.

   ```
   .env
   *.env
   .env.*
   *.key
   *.pem
   id_rsa*
   id_ed25519*
   id_ecdsa*
   .ssh
   .hermes
   .claude
   *-credentials.txt
   .git
   .venv
   venv
   node_modules
   __pycache__
   *.pyc
   (?d).DS_Store
   (?d)._*
   (?d).Spotlight-V100
   (?d).Trashes
   (?d)Thumbs.db
   (?d)desktop.ini
   (?d)~$*
   ```

3. **«Версионирование файлов»** (File Versioning) → **«Поэтапное»** (Staggered), срок хранения — **30** дней. Тогда и на компьютере у удалённых файлов будет корзина.
4. **«Сохранить»**.

Через минуту в обоих окнах у папки «Проекты» должно гореть **«Актуально»** (Up to Date), а у второго устройства — **«Подключено»**.

## Шаг 4. Проверка и фраза для Гермеса

**С компьютера на сервер.** Положи в папку `Проекты` на компьютере любой файл, например `привет.txt`. На сервере в Netcatty набери:

```bash
ls ~/Проекты
```

Файл в списке — работает.

**С сервера на компьютер.** Напиши Гермесу в Telegram: «Создай в папке ~/Проекты файл проверка.txt с текстом "работает"». Через пару секунд файл появится в папке на компьютере.

**Фраза для Гермеса.** Отправь её один раз в Telegram или во вкладку Chat веб-интерфейса — чтобы он сам складывал результаты туда, где ты их увидишь:

> Все файлы, которые создаёшь для меня, сохраняй в папку ~/Проекты. Для каждой задачи заводи там отдельную подпапку с понятным названием. Запомни это правило.

Назвал папку по-другому в шаге 1 — подставь своё название.

## Корзина версий: если что-то удалил или испортил

Когда файл удаляют или перезаписывают на одном устройстве, **второе** устройство не выбрасывает старую копию, а убирает её в скрытую папку `.stversions` внутри «Проектов». Там она лежит 30 дней. Удалил файл на компьютере — старая версия ждёт на сервере, и наоборот.

Как достать:

1. Открой окно Syncthing того устройства, где хранится старая версия (сервер — через тоннель `8385`, компьютер — `8384`).
2. Нажми на папку «Проекты» → кнопка **«Версии»** (Versions).
3. Найди файл, выбери дату → **«Восстановить»**.

Или по-простому: на сервере попроси Гермеса «Найди в ~/Проекты/.stversions прошлую версию файла такого-то и верни её на место».

## Если что-то не так

| Что видишь | Что делать |
|---|---|
| Синхронизация висит на 95% (или 99%) и не двигается | Чаще всего это `.DS_Store` в папке, которую удалили на другой стороне: Syncthing не может удалить папку, потому что в ней остался мусор Mac. Проверь, что на компьютере вставлен список из шага 3.3 со строкой `(?d).DS_Store`. Потом в окне Syncthing: папка «Проекты» → **«Пересканировать»** (Rescan) |
| У второго устройства написано «Отключено» (Disconnected) | Подожди 1–2 минуты: устройства ищут друг друга. Не помогло — проверь, что на сервере служба работает: `systemctl status syncthing@root` (должно быть `active (running)`). Если нет — `systemctl restart syncthing@root` |
| Устройства вообще не видят друг друга | Проверь, что ID вставлен целиком и без пробелов. На сервере открыты порты Syncthing: `ufw status` — в списке должны быть `22000/tcp`, `22000/udp`, `21027/udp`. Нет — запусти команду из шага 1 ещё раз, она их добавит. Даже если порты закрыты где-то у хостинга, Syncthing работает через свои промежуточные серверы, просто медленнее |
| Появился файл с `.sync-conflict-…` в имени | Один и тот же файл изменили на двух устройствах почти одновременно. Syncthing ничего не выбросил: сохранил обе версии. Открой обе, оставь нужную, лишнюю удали |
| На Mac файл или папка с русским именем появляется дважды или с ошибкой | Mac хранит русские буквы иначе, чем сервер. Syncthing обычно сам это выравнивает. Ничего не удаляй руками: подожди минуту и нажми «Пересканировать». Не помогло — скрин в чат потока |
| Файлы удваиваются, появляются копии с «(1)», «(2)» | Папка лежит внутри Яндекс.Диска, iCloud, OneDrive или Dropbox. Перенеси её в обычную домашнюю папку: в окне Syncthing на компьютере удали папку «Проекты» из списка (сами файлы останутся), перенеси, добавь заново с новым путём |
| Окно сервера `http://127.0.0.1:8385` не открывается | Тоннель не запущен или закрыт. Открой заново: окно терминала с `ssh -L 8385:127.0.0.1:8384 root@IP_сервера` (и не закрывай его) или правило в Netcatty |
| `bind: Address already in use` при запуске тоннеля | Тоннель уже открыт в другом окне. Пользуйся им или закрой лишнее окно |
| На `http://127.0.0.1:8385` открылось окно компьютера, а не сервера | В тоннеле написал `8384:` вместо `8385:` слева. Первое число — 8385 |
| Установщик пишет «Отпечаток ключа Syncthing не совпал» | Установка остановлена специально: ключ программы не тот, что ожидался. Ничего не делай руками — скрин в чат потока |

## По желанию: второй уровень — история в GitHub

Синхронизация хранит прошлые версии 30 дней. Если хочешь полную историю всех изменений проекта на годы — подключи к папке проекта git и GitHub. Как это делается, разобрано в [неделе 4](../nedelya-4-github/README.md). Папка `.git` в синхронизацию не попадает — её ведут отдельно, на одном устройстве.

## Что проверено, а что нет

- **Команды установщика** проверены на ошибки в коде, но прогон на чистом сервере ещё не записан. Если что-то пошло иначе — открой issue в этом репозитории со скрином, поправим.
- **Названия кнопок Syncthing** даны по русскому переводу программы, в скобках — английские. В твоей версии слова могут чуть отличаться.
- **Установщик для Windows** — сторонний, его рекомендует сам сайт Syncthing. Вопросы, которые он задаёт при установке, глазами не сверены.
